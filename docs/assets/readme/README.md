# README and social assets

The images of the modern-xlsx identity: the hero and the architecture picture in the root `README.md`, the mark, a favicon, and the link-preview cards. They are hand-built SVG, generated by the scripts in `src/`. None of them ships in the npm package: `packages/modern-xlsx/package.json` `files` does not include `docs/`.

## Files

| File                                              | Size                     | What it is                                                                                         | Where it is used                                                                                                                                           |
| ------------------------------------------------- | ------------------------ | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `hero-light.svg`, `hero-dark.svg`                 | 1280x320                 | The wordmark set in an active cell range on a sheet grid                                           | First screen of the root `README.md`, in a `<picture>` (the dark file for GitHub's dark theme)                                                             |
| `architecture-light.svg`, `architecture-dark.svg` | 960x1040, shown 640 wide | The read and write paths through the TypeScript API, the WASM boundary and the Rust core           | `## Architecture` in the root `README.md`, in a `<picture>`                                                                                                |

The PNG files are screenshots of their SVG sources (Chromium, device scale factor 1).

## Rules every SVG follows

GitHub and npm show these files through `<img>`, which loads no web fonts and runs no scripts, so every file is self-contained:

- The root element has `xmlns`, `viewBox`, `width`, `height`, `role="img"`, `aria-labelledby="t"` and a `<title id="t">`.
- No `<text>`: all lettering is outlined to `<path>` elements, so no font is needed to display it.
- No `<style>`, `style=`, `class=`, `<image>`, `<script>`, `<foreignObject>`, filters, gradients, `href`, CSS variables or `prefers-color-scheme` queries. Colours are literal hex values from the palette below. Light and dark are separate files, so the theme follows GitHub's setting through `<picture>` rather than the operating system's.
- Budgets (optimised bytes): mark and favicon under 3 KB, hero under 25 KB, architecture under 80 KB, each PNG under 300 KB.

`src/lib.mjs` checks each of these on every file it writes, and `src/build.sh` prints `ok` or `FAIL` per file.

## Typeface and licence

The lettering is [Geist](https://github.com/vercel/geist-font): Geist Mono SemiBold for the wordmark, Geist Mono Medium for code names, and Geist Medium and SemiBold for labels. Geist is licensed under the SIL Open Font License 1.1. The SVG files hold no font data: each letter is an outlined path, read from the font files of the npm `geist` package by opentype.js.

## Regenerating

`src/package.json` pins every tool exactly: `geist` 1.9.2, `opentype.js` 2.0.0, `svgo` 4.1.0, `github-markdown-css` 5.9.0 (for the README mock only) and, as a devDependency, `playwright` 1.66.0-alpha-2026-11-14. `src/` is a standalone npm project: it is not a pnpm workspace member and has no lockfile in the repository.

```bash
cd docs/assets/readme/src
npm install --ignore-scripts
npx playwright install chromium firefox
bash build.sh
```

`build.sh` regenerates every SVG and `architecture-alt.txt`, checks them, writes them into this directory (or into the directory given as its first argument), exports the two PNG cards and renders previews into `preview/`. Its working files go to `src/out/`. Both directories are ignored by git.

| Script                                | Writes                                                                                             |
| ------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `gen-brand.mjs`                       | `mark-light.svg`, `mark-dark.svg`, `favicon.svg`, `hero-light.svg`, `hero-dark.svg`                |
| `gen-architecture.mjs`                | `architecture-light.svg`, `architecture-dark.svg`, `architecture-alt.txt`                          |
| `gen-cards.mjs`                       | `social-preview.svg`, `og.svg` (it imports the mark and the wordmark from `gen-brand.mjs`)         |
| `lib.mjs`                             | Shared: palette, outlining, the SVG shell, the svgo pass and the rule checks                       |
| `render.mjs`, `mock.mjs`, `sheet.mjs` | Previews, the PNG export, a README mock and a contact sheet                                        |
| `measure.mjs`, `diff.mjs`, `zoom.mjs` | Raster checks (wordmark spacing, corner clipping, raw against optimised pixels) and enlarged crops |

The three generators need only the dependencies (`node gen-brand.mjs <out-dir>`, and so on); Playwright is needed for the PNG cards and the previews. Every size, position and colour is a named constant, so a change is a one-line edit and a re-run. The architecture labels name real functions: change them together with the code they describe.
